How the timer collects data 7

Starts automatically when a case is opened in the workstation (can be turned off per CM)
Records time per checklist stage; pauses with a reason
Auto-pauses after 10 min with no activity, and asks "were you still working?"
CM can correct a time with a reason (correction is logged)
Stops on "Mark IR complete"
Morale: kudos sent and received (counts only)

Design notes · Team insights (management)

  1. Shown only to people marked as managers in the roster (for example, the CM directors). Hidden in the sidebar for everyone else. After SSO, access comes from the AD group.
  2. Built for the management request: how long initial reviews take over time, especially for new employees and people newly trained on a skill.
  3. Weekly trend with new hires (< 90 days, from the profile start date) compared with experienced CMs.
  4. Per-CM view is for coaching. It is never shown to other CMs, and it is not a ranking. Default sort is by name.
  5. Uses the "trained since" date from each CM's profile training matrix, so managers can see the learning curve per skill.
  6. Stage times show which steps slow people down. This helps decide where to add guidance or training.
  7. Timer data is saved on the server with the case (case label, CM, stage, start/stop, pauses). No client data is stored in the timer records.
